My flagship work is an AI evaluation platform that connects task creation, sandbox execution, grading, human review, and audit. I bring the same systems approach to products in other domains.

AI EVALUATION · FEATURED WORK

From tasks to trusted training signals.

A trustworthy result needs a record of what ran, how it was graded, and who reviewed it.

PROBLEM

AI training tasks lose value when no one can explain how they ran, were scored, or got approved.

DESIGN

Separated sandbox execution, automated grading, human review, and audit into a service-backed workflow using FastAPI/gRPC, PostgreSQL, and GKE. Sentry tracing crossed the gateway and eight services.

IMPACT

Each accepted task carries execution, score, and approval evidence through the pipeline. Cross-service tracing exposed silent gRPC failures, while CI repairs restored 26 blocked jobs.

System visuals are illustrative. Company interfaces and source code are not shown.

02 / DATA OPERATIONS✦

The Trusted Data Pipeline

SYSTEM FLOWBuilt platform workflow
  1. 01Task APICriteria + access
  2. 02Object uploadDirect to storage
  3. 03AI workerOptional, frozen run
  4. 04Admin reviewApprove or return
SCALING DECISION

Direct uploads keep large files off app servers; each optional AI run freezes its input set.

Problem Teams need to collect and review large files without losing track of uploads, AI changes, or decisions.

Design Built task intake, direct object-store uploads, optional isolated anonymisation runs, QA findings, and a single admin approve-or-return path.

Impact File transfer bypasses app servers. Immutable run snapshots and append-only review history preserve evidence for the work that actually happened.

06 / AI GOVERNANCE✦

Can an AI Really Forget?

SYSTEM FLOWResearch prototype
  1. 01CheckpointForget set + reference
  2. 02Probe engineDirect + relearning
  3. 03Evidence scorePer-item confidence
  4. 04VerdictPass / fail / unclear
VALIDATION DECISION

Pluggable probes and reference calibration keep a direct refusal from being mistaken for proof of forgetting.

Problem Removing training data does not prove a model has forgotten it.

Design Built a method-agnostic audit with pluggable recovery probes and evidence scoring; designed a separate control plane for data lineage and erasure holds.

Impact Compatible model checkpoints can be challenged through the same evaluation path; the prototype reports inconclusive when evidence cannot support a deletion claim.
